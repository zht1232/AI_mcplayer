# 当前实现架构

当前版本为 Minecraft 26.2 的纯客户端 Fabric mod。控制对象是当前客户端登录的账号，服务器使用现有 Paper 和插件，不安装本项目服务端组件。

产品名为拾野（Wildling）。0.1.2 的 `ModelObservation` 将完整原始观察投影为按任务选择的可读视图，去除重复样式并保留可操作的槽位/点击 ID。模型可通过 `observe` 和 `inspect_slot` 请求更多数据。完整导出仍保留原始字段。

```mermaid
flowchart TD
    L[本地面板与 /aip] --> Q[ControlState：本地优先 / 公共队列 / 自主目标]
    P[其他玩家：提到名字、@名字、!ai] --> R[ChatAddressing：识别说话者与目标]
    R --> Q
    S[现有服务器] --> O[UiBridge + ClientMotor：世界 / UI / 聊天快照]
    Q --> B[AiBrain：异步 OpenAI 兼容请求]
    O --> B
    B --> T[ToolCatalog 注册工具与参数校验]
    T --> M[ClientMotor：移动、挖掘、使用物品]
    T --> H[HarvestSkill：接近 / 挖掘 / 拾取]
    H --> M
    O --> D[本地防御反射：每 tick 检查威胁]
    D --> M
    T --> U[UiBridge：槽位、Dialog、聊天与命令]
    M --> S
    U --> S
    S --> F[实际状态变化与失败反馈]
    F --> B
```

## 具体实现

| 模块 | 当前职责 |
|---|---|
| `PartnerClient` | Fabric 入口、连接生命周期、tick 调度、模型结果回到客户端线程、动作队列、取消与回调版本校验 |
| `ControlState` | 进服后手动启用、本地任务抢占、公共任务排队、自主目标、取消和停止 |
| `ChatAddressing` | 从签名聊天或带在线玩家名的插件聊天格式识别提名/@，拒绝自己的回声 |
| `AiBrain` | JDK HttpClient 异步请求、环境变量 API key、超时、响应大小限制、原生 function calling 解析；每次最多三项动作 |
| `ToolCatalog` | 模型可使用的工具及参数 schema，未知工具拒绝执行 |
| `UiBridge` | 容器名称/槽位/Lore、点击与悬停聊天组件、Dialog 标准控件、BossBar/ActionBar/Title/TAB/记分板快照；正常客户端交互 |
| `ClientMotor` | 限定范围与搜索预算的 A*、碰撞检查、逐 tick 输入、近距离挖掘/交互/进食/攻击；溺水上浮与可见近身敌对生物防御 |
| `HarvestSkill` | 接近目标、等待服务器挖掘确认、拾取、回报实际状态；单次一个可见附近资源 |
| `SpeechPolicy` | 相似消息去重；工作更新需要实际进展，并受频率限制；纯工作叙述留在本地 |
| `ScreenPolicy` | 多人 Esc 覆盖层允许世界控制；F8 与交互界面暂停世界动作 |
| `BlockFeedbackMixin` | 监听服务器方块更新，区分客户端预测与服务器确认的挖掘结果 |
| `PartnerPanel` | F8 本地控制界面、任务输入、启停、自主开关、模型与错误状态 |
| `PartnerConfig` | 当前实例的 JSON 配置与有限笔记持久化 |
| `ModelObservation` | 按聊天/行动/菜单任务压缩与选择观察，控制输入体积，保留按需查询入口 |

模型不逐 tick 控制。网络推理在异步线程执行；世界读取和动作执行留在客户端线程。世界动作通过原版客户端玩家控制与交互接口，服务器仍负责权限、领地、物品、战斗和交易判定。

发给模型的是当前结构化快照、最近聊天、最近动作结果和有限笔记。当前没有完整长期对话数据库、知识检索或完整自主生存 Goal 引擎；自然语言目标由模型循环推进，明确物品数量目标由背包计数检查。0.1.4 加入单块采集的阶段执行；自主/明确采木任务持续没有进展时触发有限恢复，成熟作物恢复只在明确请求时尝试。禁止采集/破坏的已记录边界会阻挡自动恢复；服务端仍判定实际权限。

默认每次规划后等待 2 秒。正常对话只有回复而没有后续动作时会结束当前公共任务；这包括通过 `chat_say` 工具回复的情况。附近可达位置由与寻路相同的几何规则计算，给模型提供实际可以尝试的坐标；当前仍不是图片或视频理解。

## 思考与对话

0.1.3 默认关闭本地 4B 的思考，保留 32768 上下文和可选的 256 token 思考预算。连接页将 `enableThinking`、`reasoningProtocol` 保存到配置，`ReasoningProtocol` 按后端协议写入每次请求。未知自动协议不发送扩展字段，面板保存时提示选择协议。模组读取正常 `content` 和工具调用，思考内容不发到服务器聊天。

正常对话经 `say()` 与原版聊天接口发送。状态、错误和纯工作计划留在本地；公开工作更新需有新进展，且至少间隔 30 秒，相似句另行去重。聊天命令例如 `/tpa 玩家`、`/tpaccept` 可由 `ui_input_chat` 工具执行；提示文字能进入聊天快照，真正是否接受传送由服务器插件处理。

## 参考与多模型方向

本地参考源码中的 Numen `MobDefenseChain` 通过确定性威胁检测抢占工作并执行战斗任务，`mc_aiplayer/goal/GoalExecutor` 用任务状态和结果谓词复核目标。参考实现依赖其服务端玩家/任务接口，本项目的真实客户端需要独立实现控制代码。0.1.4 补了部分采集执行和近身防御，没有移植完整参考引擎。

推荐的职责分工是：主 4B/API 理解与规划，技能状态机持续执行，逐 tick 反射处理危险。更小模型可将来用于意图识别、摘要或任务分类；共享一个动作调度器，不分别控制身体。当前未部署第二模型，也未测多模型吞吐收益。

## 验证边界

已运行传输/状态/聊天解析测试，并在隔离真实客户端与服务器验证菜单、聊天命令、Dialog、BossBar、短距离移动和挖掘。任务仍需针对正式服务器的插件组合与资源包实测。资源包图片语义目前没有视觉模型，复杂地形和长期自主生存能力没有完整成功率证据。
