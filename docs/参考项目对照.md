# 参考项目对照与采用

核对日期：2026-10-05。以下是实际读取的 GitHub 源码/配置，参考快照在本地 repos/reference-snapshots，保留了原 LICENSE；不会作为运行依赖打进模组。

| 项目 | 读取的部分 | 当前采用与适配 |
|---|---|---|
| [Mindcraft](https://github.com/mindcraft-bots/mindcraft) | agent.js、self_prompter.js、modes.js、history.js、library/skills.js、settings.js、默认 profile | 过滤自己的聊天；来源明确的对话历史；独立保命模式；连续执行动作；无动作循环检测。参考配置已拉取，Fabric 使用自己的接口实现。 |
| [Numen](https://github.com/Dwinovo/minecraft-numen) | 本地源码的 MobDefenseChain、任务抢占/归还、碰撞规划 | 防御与脱困同属紧急任务，避免争抢身体；真实碰撞几何驱动；危险中取消旧模型回复。没有把依赖服务端玩家的类直接搬到客户端。 |
| [mc_aiplayer](https://github.com/zoyluoblue/mc_aiplayer) | GoalExecutor、GoalPredicates、任务状态与结果复核 | 资源任务使用背包增量谓词；连续数量采集；失败退避，不凭口头报告判定完成。 |
| [Voyager](https://github.com/MineDojo/Voyager) | skill.py、critic.py、README 的技能学习流程 | 分层技能目录、经验按需检索、执行反馈和结果验证。当前实现知识积累，不复制其 Python/Mineflayer 代码生成运行器，也不声称自动训练模型参数。 |
| [mineflayer-collectblock](https://github.com/PrismarineJS/mineflayer-collectblock) | CollectBlock.ts 与配置参数 | 接近、挖掘、拾取、数量检查作为连续工作；满背包才考虑整理。其 JS 不能直接操作 Fabric 客户端，按同类状态机实现。 |
| [mineflayer-statemachine](https://github.com/PrismarineJS/mineflayer-statemachine) | statemachine.ts、README | 按阶段进入/退出，异常和高优先级工作抢占；明确保持工作状态。 |

Mindcraft、mc_aiplayer、Voyager 和两个 PrismarineJS 库均已核对为 MIT；Numen 为 LGPL-3.0。当前产品代码主要采用职责划分与状态机经验，没有将参考仓库作为依赖或直接移植其服务端控制代码。引用配置仅存放在本地参考目录并保留许可。

当前真正缺少的仍是完整的长期生存任务图、复杂合成/种植流程和正式服自定义作物/反作弊组合验收。增加模型或记忆文件无法自动替代这些执行代码和验证。
