# 纯客户端模组开发计划

用户已于 2026-10-04 明确要求开始构建，目标为 Minecraft 26.2 纯客户端模组。服务器无需安装本项目插件。装有模组的客户端进入服务器后，用户才能开启 AI 功能；模组控制当前登录的账号。退出服务器后停止动作和推理，重连后由用户重新开启。

## 实施与验收

1. 建立 Fabric 26.2 / Java 25 工程，固定构建依赖并产出客户端 jar。
2. 完成进服门控、启停、紧急停止、配置和本地控制命令；模型请求异步运行，旧会话结果不能作用于新会话。
3. 接入通用容器、物品名称/Lore、左右键与 Shift 交互，保留聊天点击/悬停组件；捕获 BossBar、ActionBar、Title、TAB 和侧边栏等客户端数据。
4. 接入本地或 API 的 OpenAI 兼容模型，注册有明确参数的动作，保留实际结果；建立有限频率的自主规划循环和确定性执行。
5. 实现首批生存动作：有限区域内移动、采集、放置、已有食物进食、攻击/避险，以及容器交互；不能由源码存在推导为任意地形可靠。
6. 运行编译、决策传输与生命周期测试、隔离客户端启动验证，打包 jar 和中文说明。实际 DeluxeMenus、QuickShop、AuthMe 及其余插件兼容需在对应服务器上验证；未进行的验证明确标出。

## 范围

- 首版纯客户端，复用服务器现有 LuckPerms 与其他插件判定。
- 本地 4B/7B 和 API 通过配置选择；不在开发期间产生付费模型调用。
- 工具和 UI 状态结构化传给模型；资源包图形语义按本服映射或后续视觉接入处理。
- 控制入口为客户端本地命令与面板，公共聊天不自动作为主人指令。
- 高成本的长距离导航、完整科技树、复杂建筑与全插件业务攻略后续逐步增强；首版现有能力需要真实反馈与失败处理。

## 工作分工

- 主任务：构建、生命周期、配置、执行层、控制入口、集成和打包。
- 模型子任务：独立的异步模型传输、工具调用验证及本地 HTTP 测试。
- UI 子任务：菜单/HUD/聊天感知与正常客户端 UI 操作。

## 当前环境限制

已有 Java 25。本机未挂载 H 盘，也没有资料中 G 盘服务器目录；开发可继续，模型文件与服务器实测在实际运行环境核对。
